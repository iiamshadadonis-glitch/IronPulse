# V1.51 verification

Final accepted results: **27 code/database/cache check groups and 12 browser regression suites passed**. The complete project was tested locally, including an extracted candidate. The final source matches the tested file hashes.

| ZIP CRC, two independent extractors and per-file SHA-256 comparison | Release gate enforced |

Browser checks used Chromium 153 with mobile viewport emulation, including 320px, 390px and 430px widths, short screens, and desktop breakpoint checks. API responses were local sample data. The database tests used temporary SQLite databases; Edge Cache tests used a local Cache API simulation. No production deployment, live financial transaction, real email delivery, physical Safari device or installed Google Meet app was tested. Cache API storage is regional; in-flight deduplication is per client/Worker isolate rather than a new global lock.

The initial batch included a subscription-card timing failure and a Brand suite time limit. The subscription assertion now waits for the existing Apply busy state. Both suites passed when rerun. Final custom-page testing also caught a pre-load variable guard, which was corrected; the full code command and public/Student browser suite then passed again. The attempts and exact selected evidence are recorded in verification/v1.51/verification-scope.json.

Commands: `npm run test:dance-v1.51`, `npm run test:dance-v1.51:browser`, the retained `tools/verify-mobile-v1-49-*.mjs` suites, and `node tools/verify-v1-50-layouts.mjs`. Browser commands require an installed Playwright module and Chromium; the tool scripts support DROPBEAT_PLAYWRIGHT_MODULE and DROPBEAT_CHROMIUM_PATH.

The replacement archive uses ordinary ZIP/Deflate compression, no encryption and no ZIP64. It is closed and synced before delivery, checked by Python and Info-ZIP, independently extracted with both, and compared against every packaged file. A saved-download readback is also required before the link is delivered.
