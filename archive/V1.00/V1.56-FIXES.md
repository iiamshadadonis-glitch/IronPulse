# V1.56 — Dynamic Button Dictionary

This complete replacement starts from the supplied V1.55 project. It retains the earlier fixes and adds the following feature.

## Admin editor and safeguards

- **Settings → Pages → Buttons** is a new primary tab with **Front-End Buttons** and **Admin Panel Buttons** categories.
- Numbered rows reuse the Website Header Order row/badge structure, with a compact label and an accessible pencil action.
- Desktop editing uses a centered dialog. Mobile editing uses a full-screen, two-step **Button Details → Review** wizard with a scrolling body, padded header and anchored safe-area footer.
- Both label and URL/action slug are editable. Labels support plain text; destinations support local paths, HTTPS URLs and the button's original native action slug.
- Every save and reset opens a warning. Only typing the exact lowercase word **confirm** enables the red final action. Desktop warnings are centered dialogs; mobile warnings are bottom sheets. Cancel/Close does not write anything.
- **Reset to Default** restores all 33 entries in both categories to their original labels and destinations.
- Authentication and confirmation are enforced by the API as well as the UI. Atomic revision checks reject a stale save rather than overwriting another Admin's edit. Unsafe destinations, unknown actions and invalid labels are rejected.

## Front-end bindings

A single default registry is shared by the browser and server. The public endpoint returns only the 29 front-end entries. The four Admin entries are available through the authenticated endpoint.

The bindings update existing controls rather than replacing their handlers. Cart badges, selected product IDs, icons, form validation, authentication and native expand/collapse actions are retained when the original action slug is kept. Controls showing a disabled/full/busy state keep that state. Changing a native action to a URL deliberately turns that control into navigation to the configured destination.

The required inventory includes **Checkout, Book a Trial, Explore Dance Plans, My Membership, Discover DropBeat, Book the Class, Book Now, Details, See All Plans, Login, Sign Up, Student Sign Up, See more and See less**. Additional existing Google/Coach authentication, trial/contact/request submission, story and plan actions are included. A Sign Up link is bound wherever that optional link is present; the existing Student Sign Up tab remains a separate action. Website Header Order continues to control ordinary menu labels; a configured Login dictionary override takes precedence for the Login action, and resetting restores the menu's own configured label.

Admin entries cover **Create Subscription, Add New Plan / Offer, Download Sample CSV and Create New Page**. Other application and destructive controls keep their existing labels and business behavior.

## Persistence and synchronization

- The dictionary is one JSON document at `settings.key = 'button_dictionary'` in the existing D1 settings table. No new table, migration, package or deployment secret is required.
- Successful saves/reset invalidate the dictionary Edge entry before returning. The save response updates the editor directly without an extra dictionary GET.
- The existing client SWR cache is reused. A page load shows cached data immediately and silently validates it; refresh, back/forward return and successful Admin-save notifications also update the dictionary. Already-open public tabs receive the existing cross-tab invalidation signal.
- Normal public API responses use the existing Cloudflare Cache API helper. Warm normal requests avoid database reads. Explicit freshness checks read one indexed settings row, with simultaneous requests deduplicated. There is no dictionary polling timer or extra focus listener.
- Older responses cannot overwrite a newer revision. If the endpoint is temporarily unavailable, existing/default controls remain usable.
