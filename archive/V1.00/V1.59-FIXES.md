# V1.59 fixes

This complete replacement is based on the supplied V1.58 archive. All 1,725 original files are retained; 1,676 are unchanged byte for byte. The 49 intentional modifications and their before/after hashes are recorded in `verification/v1.59/source-scope.json`.

## Stable dynamic navigation

The Admin sidebar, public header/footer and dynamic navigation builder now consume the existing Layout/Buttons stores from a null initial state. The legacy writers that repeatedly restored Article or Dance Tips no longer own navigation labels. Saved default names are explicitly owned too, fixing the case where Dance Tips matched the default and was previously left open to legacy rewrites.

Critical head styles show gray placeholders before configuration is available. An unavailable, malformed or stalled initial response shows Retry rather than a hardcoded old label. Later failures retain the last valid state. Public/shared labels update before paint; repeatedly rendering the UI does not fetch data. Concurrent refreshes share one request, Admin dictionary data is not persisted, and normal navigation returns respect the existing one-minute revalidation budget.

The original navigation nodes, cart counts, click handlers and child-page destinations are retained. A renamed Pricing parent does not overwrite a Memberships child. Repeated sidebar normalization reuses existing groups instead of rebuilding the whole sidebar. Mobile More navigation clears obsolete fit styling when additional tabs arrive. Malformed cached button-editor data is rejected safely instead of throwing during rendering.

## Reliable Schedule lifecycle

The Schedule loader is explicitly registered with the shared router. Desktop and mobile use the same bounded request/error lifecycle. Both the fetch and response parsing are covered by a 15-second timeout. HTTP failures, invalid JSON, unexpected nested data and renderer errors leave loading and display Failed to load schedule data with Retry.

The Schedule, Leaves and Holidays tabs do not wait for that request. Successful refreshes preserve the current selection; superseded/late responses cannot replace newer data. Mobile keeps the existing 50-record page requests and Load More behavior. The desktop endpoint and backend SQL are unchanged.

Desktop-only CSS restores inner card padding and 24px separation between Studio Schedule's description and the controls below. This spacing rule begins above 760px and does not alter the mobile layout.

## Preserved scope

No database schema, backend business query, payment/refund rule, authentication/session rule, notification delivery rule, integration configuration, theme palette or dependency is changed in this release. Middleware changes only deliver the versioned presentation assets. Existing PWA sessions, notifications, imports, forms and saved Layout/Buttons features remain in the complete project and were included in retained regression testing.

New production code consists of the small shared loading/error helper and its CSS. Tests, release notes and final verification logs are included. Browser binaries, installed dependencies, browser profiles, screenshots and nested release ZIPs are excluded.
