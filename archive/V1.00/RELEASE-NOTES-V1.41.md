# V1.41 fixes

These changes apply to mobile viewports up to 760px. The original desktop layouts, saved brand colors, database schema, authentication, payment calculations and gateway handlers are retained.

1. **One client summary component everywhere.** Search Customer, Total Leads, Hot Leads, Recent Leads, Active Subscribers and the other dashboard client lists use the existing single `clientCard()` renderer and one global style contract. The name and latest-date pill stay on the same row. Email/phone and next action/follow-up use the same compact two-column grid. Each client occupies one full-width list card. The first three recent-page chips stay compact; all pages remain available in Client Details.
2. **Visitors and Repeat Visitors.** Replaced the mobile desktop-grid presentation with individual cards. Identity, IP, location and device information occupy the left side; visit date, time and count align on the right. Sources and page badges wrap inside the record. Headers and horizontal list scrolling are removed on phones.
3. **Traffic Sources.** Removed the overlapping parent-grid presentation. Each source has its own card, with its title above a compact two-column metrics grid. The overview metrics also follow the shared two-card carousel rule.
4. **Subscription and payment detail lists.** The shared conversion now recognizes the older grid/head/row variants used by total, active, new, failed and cancelled subscriptions, successful charges, renewals, upcoming renewals and other overview detail lists. Customer/name/ID stays at the top; labelled details and long emails wrap within the card. Native table headers are hidden only on mobile. Raw source CSS prevents a desktop table flashing while refreshed rows are being enhanced.
5. **Saved product-image ordering.** In Product Images → Scrolling Images, saved images use up/down controls on mobile while retaining the original reorder handler and direction values. The compact thumbnail, alternate text, cover control, sort controls and Remove button fit together. A 320×568 phone can display the whole first saved-image card and more than half the next image. Desktop left/right ordering remains unchanged.
6. **Sales navigation.** The mobile Create Subscription tab reads `+ Subscription` on one line. The desktop label remains Create Subscription.
7. **Growth Analytics filter FAB.** Removed the filter trigger from the top title row. A fixed, brand-colored, icon-plus-Filter button remains visible while scrolling in every Growth Analytics mode. It opens the existing reusable filter sheet with the original Apply behavior.
8. **Tabs versus segmented controls.** Shared mobile category navigation uses horizontal text tabs with an active underline. Calendar/list and similar secondary view controls use compact segments. Growth Analytics adds Day/Week/Month shortcuts through the existing period filter. Chart-type selectors in Growth and Marketing Analytics share the same icon-only segmented-control renderer. Existing chart, category and notification handlers remain in charge.
9. **Calendar list tap affordance.** Analytics date rows have a stronger brand-colored chevron, a minimum 48px full-row target, touch feedback and keyboard activation. The selected-day breakdown continues opening in the compact sheet.
10. **Consistent information helpers.** A window-level mobile help interceptor runs before legacy document-level flip listeners. It restores the underlying page, including fronts identified only by data attributes, and displays the existing help in the shared sheet. Helpers share a drag handle, clear title, top-right Close and full-width Done button. Desktop help interactions are unchanged.
11. **Most Visited data and duplication.** Removed the legacy mobile Most Visited wrapper/header. The toggle reveals the actual saved page chips directly beneath the toggle row, in one horizontally scrollable line. Late-arriving chip data replaces the empty state correctly. Visit Info and Source remain separate controls.
12. **Send Statement.** Payment Statement opens as a bottom sheet above Client Details. Header help and Close share one row. Statement, WhatsApp and Gmail actions fit in one compact row; Statement uses a download icon. The floating filter control opens the shared filter sheet: Statement Period spans the first row and From/To share the next. Old filter controls are retired when switching between statement and invoice views. The existing PDF and sharing handlers are preserved.
13. **Generate Invoice.** Payment and refund invoice forms open above Client Details in the mobile full-screen document view. The invoice wizard separates Customer Details, Billing & Plans, Terms & Notes and a read-only Review. Original PDF/WhatsApp/Gmail actions appear only on Review. Back retains entered values, and the header/scroll body/footer have explicit height constraints.
14. **Client Refunds.** Refresh shares the Refunds title row. The inline refund editor becomes a clickable Refund Details row that opens a full-screen Customer Details → Payment Details → Refund Details → Review wizard. Payment records and refund history become mobile cards without horizontal headers. Tapping a payment card uses the original selection handler to prefill the same wizard. Amount validation remains active. The red Refund action appears only on Review and opens the existing approval dialog; approval is still required before the original gateway request.
15. **Layering and lifecycle.** Modal stacking follows opening order, rather than the order dialogs happen to appear in the HTML. Escape closes the top sheet first. Statement sheets support a downward header/handle gesture. The controller watches existing hidden dialogs as well as newly mounted ones, so later API responses receive the same layouts. Strict header/row matching keeps crop-editor layouts out of the record converter.
16. **Delivery stability and cache busting.** V1.41 has one guarded mobile controller. All three dashboard shells and Pages Functions delivery retire V1.36–V1.40 controllers, load the V1.41 assets and retain no-store dashboard HTML. Changed shared CRM/help presentation scripts have fresh build URLs. Metric groups clear obsolete dots when refreshed to zero/one card, and pagination adapts when the number of rows changes. Dark-mode wizard labels and secondary actions use the existing readable theme text color. No new recurring polling timer or direct API request is introduced by the mobile layer.

The complete replacement retains all earlier V1.40 work, including Bulk Plan Upload, functional mobile form Review steps, attendance/card alignment, the two-card metric carousel with a maximum of two balanced rows, and touch chart scrolling. The V1.41 renderer changes are presentation and navigation adapters around the existing controls and actions.
