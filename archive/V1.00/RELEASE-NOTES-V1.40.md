# V1.40 fixes

Unless stated otherwise, these changes apply only at mobile widths of 760px or less. Existing desktop presentation and saved brand colors remain in charge.

1. **Search Customer:** one full-width result card per row, with email/phone and next action/follow-up beside each other. Reduced padding and chip sizes; only the first three visited-page badges appear here. The full page list remains available in Client Details. Other customer-card grids retain their existing column rules.
2. **Search controls:** the query stays full width. From, To and Search share the next row.
3. **Client Details:** corrected the squeezed Website Visits card; all four stats share equal two-card carousel widths. Reduced stat height and fixed time-part spacing.
4. **Client header and footer:** smaller status/favorite/lifecycle/refresh controls, compact action buttons and fitted tab capsules. The modal uses the full viewport. Its content scrolls without trapping the summary below an oversized fixed header.
5. **Visit metadata:** Visit Info, Source and Most Visited are three compact, initially collapsed controls beneath the stats. Each reveals the original saved information.
6. **Independent Review:** every mobile form handled by the shared wizard now ends in a separate, read-only Review step. Back retains entered values. Passwords are excluded from the summary. Original save/post handlers remain responsible for submission.
7. **Add/Edit Plan:** Plan Basics → Pricing & Billing → Class & Schedule → Plan Features → Review. Features no longer share the final review page.
8. **Product Images:** replaced the blank mobile layout and unrelated generic steps with Upload → Social Status → Scrolling Images → Review. Upload/URL, alt text and cover controls occupy Upload. The existing optional social-status switch and its dependent fields occupy Social Status.
9. **Image ordering and saving:** the Scrolling Images step includes the new staged image along with saved images, supports moving the staged image, and shows the selected order in Review. Saving uses the existing upload, crop and image-move handlers. Mobile crop canvases stay within the viewport.
10. **Async form submission:** prevented browser navigation while existing asynchronous submit handlers load their integration settings. This fixes the mobile image-save page reload without replacing the upload handler.
11. **Bulk Plan Upload — desktop and mobile:** renamed Bulk Product Upload and Import Products. Rebuilt the CSV sample and importer for current plan pricing, offers, billing interval, trials, features, eligibility, capacity thresholds, class/coach/schedule, access dates, reminders, placements and three optional image URLs.
12. **CSV correctness:** empty cells, quoted commas, escaped quotes, multiline descriptions and BOM are preserved. Invalid rows report their row number. Stable SKUs update existing plans; duplicate SKUs and image links are handled. Existing admin authorization and plan/class validation are reused. Bulk import does not create gateway plans or publish social posts.
13. **Bulk mobile UI:** sample download becomes a header icon. The long column description is hidden on mobile. Import results identify saved plans and row errors.
14. **Header actions:** removed the space reserved for obsolete order-header controls so related search, help and download icons align at the right edge of their title row. Order notifications remain on navigation choices.
15. **Refund help:** moved the information control into the expanded provider body, above search, and removed its absolute-positioned toolbar behavior so it cannot collide with the accordion arrow.
16. **Nested records:** individual contact, subscriber, plan, order and session record borders use the live primary theme variable. Outer panel borders and stat-card borders are preserved.
17. **Global filters:** Growth modes, Marketing Analytics/Heat Maps, Attendance, subscription/source dialogs, subscription overview and portal statement filters use one reusable filter-icon/bottom-sheet pattern. Original live controls stay in their original panel scope. Apply runs the original action and closes the sheet. Nested selection/date sheets preserve the filter form.
18. **Filter grid:** visible fields are counted dynamically. Odd counts make only the first field full width; even counts use two columns. Apply is excluded. Labels and input padding are compact.
19. **Growth metrics:** reduced card padding and height while retaining the existing two-card viewport, pagination and maximum two balanced rows.
20. **Analytics Calendar:** daily totals use two columns, with the fifth total spanning the final row. List dates use compact rows with date left, net received right and a chevron. Tapping a day opens a key/value breakdown sheet instead of placing the breakdown below the whole list. Status chips stay in one horizontally scrollable row.
21. **Class and attendance details:** shared rigid 40%/60% label/value columns across Online, Offline, Demo and Attendance. Removed Students/Actions/Present/Review indentation and capped counters, status pills and edit controls. Reduced class-calendar instructional heading/subtext.
22. **Dance Tips:** Post New Dance Tip and Add Advertisement use a right chevron and open a mobile full-screen form. The information control keeps its original placement. Forms use functional steps, validation, Back/Continue and an independent Review. Labels and helper text are smaller.
23. **Delivery stability:** V1.40 uses one active mobile controller. Both the HTML shells and Functions delivery path retire the earlier controllers. Dashboard HTML uses no-store and the replacement assets use fresh filenames/build URLs.

Authentication, checkout/payment calculations, gateway integration code, class/attendance calculations, core CRM data operations and saved theme settings are preserved. The bulk importer is the intentional server-side extension; the normal plan-create behavior remains the default.
