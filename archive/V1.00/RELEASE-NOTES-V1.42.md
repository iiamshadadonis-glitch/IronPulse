# DropBeat Dance Studio V1.42 — fixes in this replacement

This is the complete replacement application, based on the attached V1.41 ZIP. It retains the existing website, dashboards, Pages Functions, migrations, integrations and original financial handlers. Every replacement includes its own fix list.

## Mobile changes

1. **One disclosure indicator.** The shared `DropBeatUI.disclosure()` primitive uses the exact `m9 5 7 7-7 7` path from Refund Details, a 20 × 20 viewport and a 1.8 stroke. Isolated CSS and inline geometry prevent inherited icon sizes, fills or stroke weights. The color resolves from the saved primary theme color. Dance Tip/Advertisement rows, analytics Calendar list rows, Refund Details, provider refund routes, post types, engagement navigation and template cards use this same primitive. Previous text-arrow pseudo-elements are suppressed.
2. **Notification badges fit inside their tab bars.** Shared mobile tab wrappers reserve 12px at the top of their horizontal scroll area. Badges have explicit layering; safe outer wrappers retain visible overflow. Orders, Inquiries and other navigation counts retain their existing data and click handlers.
3. **Direct refund navigation.** Orders & Leads → Refunds exposes a persistent Order ID/Phone search field and four full-width routes for Razorpay, Stripe, PhonePe and Manual Record. Provider accordions and intermediate Open buttons are removed from the mobile presentation. A route opens the existing live form directly in a full-screen wizard. Entered search text is passed to the original provider lookup, and the original result/prefill/refund logic remains in charge.
4. **Grouped Refund Records actions.** Search and download share one header-actions wrapper at the far right, with the title on the left and a consistent icon gap. The records list remains available below the refund routes.
5. **Help always uses the current view.** Each mobile Help tap invokes the current original help renderer and copies fresh content into the shared sheet. Previously rendered HTML is never treated as a help cache. The top Growth Analytics helper also resolves the current Business/Visitors/Leads/Coach view. Temporary desktop flip state is restored before displaying the sheet. The handle, title, Close and Done controls remain consistent.
6. **Heat Maps actions match Growth Analytics.** Help moves to the top-right section header. Its obsolete empty toolbar is collapsed. Filter becomes an extended, theme-colored, shadowed button fixed to the bottom-right of the viewport. It opens the same existing global filter bottom sheet, including nested selectors and the odd/even field layout.
7. **Post creation uses direct navigation rows.** Text, Image, Image Carousel, Video Carousel, Image + Video Carousel, Video, Story/Status and Scheduling are discoverable in a single list. The existing Poll composer remains available as a Poll Post row. Creation rows open the form directly; carousel accordion taps and blue Open buttons are absent on mobile.
8. **Explicit post wizard steps.** Text, Image, Video and Story/Status have one actionable Content & Settings step followed by a separate Review & Publish step. Image/Video include their media fields in the first step. Image, Video and Mixed Carousels have Media Assembly, Content & Settings, then Review & Publish. The instruction-only step is removed. Capability help stays behind the header information button. Story adds the optional Tags and Poll controls using the already-supported post metadata and poll payload. Existing API capability restrictions are preserved, including conditional Story caption availability.
9. **Native media selection and stable drafts.** Social post file inputs use a full-width dashed upload area with an upload icon and selected filename, backed by the original input and Drive upload handler. The upload action preserves standard-post field values across the original form re-render. Carousel uploads and Add More keep the selected full-screen flow open. Review includes media previews. Required content, uploaded media, platform selection, future scheduling and enabled-poll validation run before Continue; publishing controls appear only on Review.
10. **Compact Social form typography and spacing.** Labels, input values and helper copy use mobile sizing. Input blocks have consistent separation. Switches have fixed pill dimensions so optional Poll and Schedule controls do not stretch. Header help and Close actions remain associated with the open form.
11. **Shared mobile scheduling calendar styling.** Posts scheduling uses the same mobile-calendar contract as Online Classes: no internal borders, date numbers with event dots, circular active dates and an agenda on date selection. Month/Year is centered between previous/next controls. Today, Calendar, List and Run Due Now sit in one secondary row below the calendar. Scheduling opens as a dedicated mobile view with Back to Post Types. Original month, view, post-detail and scheduler handlers remain authoritative.
12. **Automation lists and actions.** Flow Builder and Lead Email Follow-up flat desktop cell grids become labeled mobile cards with their original edit, enable, duplicate and delete controls. Run Due Now/New Flow/New Automation actions stay in one horizontal row. Template categories swipe horizontally in one chip row. Entire template cards are tappable and use the shared disclosure instead of a large Use Template button.
13. **Automation Trigger no longer traps the user.** Selecting a template opens step settings in a bounded mobile bottom sheet over the workflow canvas. It has a top-right Close control, drag-handle styling and a dismissible backdrop. Applying valid settings closes the sheet and removes the backdrop; the trigger card can reopen it. Changing a conditional trigger keeps its settings available. Back still closes the workflow workspace. Applying settings does not activate or save an automation to the server.

## Explicit desktop change

14. **Compact Dot + Text chart legends on desktop and mobile.** Growth and Marketing legends use compact pills, small circular dots and reduced typography. Growth's original color inputs, saved palette and input handlers remain active under the compact surface. Help legend dots share the same proportions. No chart data, aggregation, values or series colors are changed.

All other layout changes are limited to mobile viewports of 760px or less. Desktop forms, navigation, calendars and financial behavior remain in their existing presentation. The shared controller is used by Admin, Coach and Student shells; features absent from a particular portal are not added to it.

## Delivery and maintenance

- Versioned V1.42 presentation assets and middleware load one mobile controller, replacing older active controllers. Dashboard HTML keeps its existing no-store delivery policy.
- The modified email-automation UI script has a new build query. Existing backend modules and configuration are retained.
- New clickable mobile navigation rows should use `DropBeatUI.disclosure()` and the `.db142-navigation-row` contract. Do not add text `>`/`›` glyphs or locally resized SVG copies. Calendar adapters call `DropBeatUI.calendar()` and preserve original date-selection handlers.
- `DANCE-STUDIO-V1.42-VERIFICATION.md` documents the regression and browser checks. `V1.42-RELEASE-MANIFEST.json` lists added/changed files and SHA-256 hashes relative to the supplied V1.41 package.
