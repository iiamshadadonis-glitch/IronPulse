# V16.97 Complete Replacement

## Contacts

- Replaced the crowded contacts list with a fixed CSS grid containing only selection, Name, Phone/Email, Location, Source and Last Updated.
- A missing genuine name now displays **Not applicable**; phone numbers and social handles are never substituted into the Name column.
- Phone/WhatsApp, Gmail and supported social profile identifiers are clickable in the grid, contact dialog and spreadsheet download.
- Alternate profile-URL metadata is hidden. Alternate names, phones, email addresses and social IDs remain grouped only when a true alternative exists.
- Operational downloads use an Excel-compatible workbook with clickable links. Marketing-ready downloads continue to exclude IP addresses and device IDs and require advertising consent.
- Contacts and the Visitors dialog now use the latest available consented IP address even when the newest page-view row has no IP value.
- A later genuine name can replace a generated social handle or generic placeholder while preserving the old value as alternate history.

## Webinars

- Online Classes, Offline Classes and Demo/Webinar now expose only **Scheduled Events** and **Members**.
- **Schedule Meeting** opens a modal with existing-customer search, new-customer entry, Meet Now/Schedule Meeting selection, provider, contact, schedule and reminder controls.
- Selecting an existing customer fills name, WhatsApp, email, Contact Phone and Contact Email.
- Scheduled events and member lists remain visible as complete CSS grids when empty.
- Members are divided into Current and Past, with fees, event time, last attendance, status and a details editor.
- Scheduling a new attendee merges their identity into Contacts without triggering an unrelated nurture sequence. Existing branded email and WhatsApp confirmations remain in use.

## Deployment

No separate D1 migration command is required for this replacement. The existing guarded schema initializer adds the new `webinar_members` table and index on the first authenticated marketing/webinar API request after the code is deployed.
