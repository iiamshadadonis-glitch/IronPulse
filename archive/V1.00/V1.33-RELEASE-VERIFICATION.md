# V1.33 Release Verification

## Root-cause audit

The supplied V1.32 archive did contain the three new presentation assets. However, it reused the V1.32 cache key, relied on the deployed HTML shell to discover them, and its deploy command targeted `dance-class` while the supplied production hostname and configuration identify `dance-class-at2`. This made it possible to deploy successfully without changing the site the user was viewing, or to keep receiving an older HTML/asset combination.

## V1.33 delivery safeguards

- Unique release files:
  - `/admin/dropbeat-admin-v1-33.css?build=dropbeat-1.33-20261012`
  - `/admin/dropbeat-admin-v1-33.js?build=dropbeat-1.33-20261012`
  - `/assets/dropbeat-mobile-v1-33.css?build=dropbeat-1.33-20261012`
- Admin preloads the V1.33 files and applies the stylesheet as the final cascade layer.
- All static and dynamic public documents load the new mobile stylesheet.
- Middleware injects V1.33 into any HTML document that does not already contain it.
- HTML responses disable browser and CDN storage and expose `X-DropBeat-Release: 1.33.0`.
- Package and Wrangler deployment targets are `dance-class-at2`.

## Preserved logic

Automated SHA-256 assertions verify that authentication, order creation, payment gateways, D1 schema, public application logic, portal dashboard logic, core Admin logic, and current visitor/email/studio logic are unchanged from the supplied V1.32 archive.

## Test command

```bash
npm run test:dance-v1.33
```

This command first verifies V1.33 asset delivery, dark-mode selectors, responsive layouts, Cloudflare cache policy, project target, syntax, and business-logic hashes, then runs the complete inherited regression chain through V1.32 and all earlier release suites.
