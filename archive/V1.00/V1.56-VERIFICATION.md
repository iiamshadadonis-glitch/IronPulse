## Preservation and limits

The supplied V1.55 ZIP passed CRC verification before extraction. Every original file is retained: **1,615 original files, 1,584 byte-identical, 31 intentional edits**. Existing application/financial/authentication handlers, upload/filter controllers, integrations, theme definitions, dependency lockfile, migrations and database/deployment configuration are unchanged. Edited HTML files add the new versioned entry points; middleware extends dictionary delivery/cache handling and updates the release header. New implementation is isolated in the V1.56 files.

Local browser tests simulate external APIs. Real production Cloudflare/D1, payment gateways, email delivery and OAuth accounts were **not** contacted; no deployment was performed. The SQLite and Cache API fixtures establish the tested SQL, handler and cache behavior without claiming a live-production test.

To reproduce code checks, use Node.js 24 or later and run `npm run test:dance-v1.56`. For browser checks, provide installed Playwright/Chromium through `DROPBEAT_PLAYWRIGHT_MODULE` and `DROPBEAT_CHROMIUM_PATH`; set `DROPBEAT_TEST_OUTPUT` outside the project. Run the commands above. Historical version-specific tests retain their historical size/version expectations; the V1.56 command is the current regression entry point.

The complete replacement uses standard Deflate, without encryption, split volumes or ZIP64. Delivery checks verify Python/Info-ZIP CRC integrity, independently extract using both tools and compare every extracted file to the tested source with SHA-256. They also verify Windows-compatible names, no duplicate/case-colliding paths and a complete single project root. The saved downloadable copy is checked again for exact byte equality, CRC integrity and entry hashes. `V1.56-MANIFEST.sha256` covers every other project file.
