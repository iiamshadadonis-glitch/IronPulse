# V1.50 completed fixes

This complete replacement starts from the supplied, intact V1.49 Verified project. Every V1.49 file and fix is retained. No dependency installation, database migration, new Cloudflare binding or theme-color change is required for these fixes.

1. **Payment Records on mobile:** the full-screen view keeps a fixed header and a flexing, independently scrolling body. Its inherited desktop 300/330px nested-list cap is removed only in this destination. Nine records and the final card are reachable at 320×568, 390×844 and 430×932. Existing pagination, record actions and payment calculations are retained.
2. **Pages submenu rows on mobile:** child entries use one non-wrapping row, a shrinking 14px input, and a fixed group of three flat 44px touch targets containing 18px icons. Their existing rename, reorder and Edit handlers remain attached. Desktop layout is unchanged.
3. **Homepage Welcome section on mobile:** the saved studio image fills the card behind the existing welcome text, bullets and Discover action. A dark gradient keeps the text readable. Existing image slides and controls remain in use; desktop retains its original columns.
4. **Public membership cards on mobile:** Home, Offers, Festival and Yearly grids use two columns. Original price, availability and action nodes are grouped into a footer with automatic top margin. Per-row measurements align prices and buttons despite differing descriptions, trial prices and features. Images scale with the card width. Desktop restores the original nodes and order; checkout, prices, availability and Details links keep their existing handlers. The polished renderer now records and announces its render, as the base renderer already does, so class/session details still hydrate when cached data arrives before the enhancement script.
5. **Browser SWR and request coalescing:** the existing plain-JavaScript API helpers share a bounded query cache. Stable admin configuration reads are memory-only, with 60-second freshness. Allowlisted public JSON can be reused across pages in the same browser tab, with 120-second freshness and a five-minute maximum age. Concurrent identical reads share one request. Stale access revalidates in the background, with at least one minute between checks. There is no added polling or window-focus refresh. Authentication, payment execution, live client records and tracking requests are not put in this shared query cache.
6. **Cloudflare D1 protection:** the existing public Cache API helper now implements SWR explicitly using timestamps, single-flight loads and a bounded stale lifetime. Warm public responses are checked before schema preparation, so a warm request avoids both schema and endpoint D1 reads. Studio Gallery also uses this helper. Keys retain origin, endpoint and semantic page/filter identity; cache-busting timestamps do not create new entries. A browser background request waits for the same deduplicated Edge refresh, avoiding two stacked stale lifetimes. Errors/private responses are not cached, stale failures are throttled, and a late request cannot repopulate a purged entry.
7. **Safe post-save updates:** Settings already returns its normalized saved object; the client now reuses that object for the next Settings load instead of making another GET. Successful admin/profile writes invalidate public snapshots across same-origin browser tabs without issuing a new request. Other writes retain their existing authoritative reload when the API returns only an ID/OK flag, preserving server calculations and validation.
8. **Delivery:** new, small V1.50 assets are added to the tested V1.49 controllers. Changed scripts have updated cache build keys. Earlier controllers, documentation, migrations and configuration are retained. The ZIP uses normal lossless compression; its complete file list, CRC and extracted file hashes are checked before and after saving the download.

## Cache boundaries

Cache API storage is local to a Cloudflare data center. In-flight coalescing is per Worker isolate; a cold/evicted cache or another data center may still read D1. Cache API hits still invoke the Worker, whereas a fresh browser-cache hit avoids that network request. This release introduces no D1-based cache bookkeeping, extra timers, KV, Durable Objects or global purge services. The short freshness/stale limits also bound updates from other administrators or external systems.

The project uses plain JavaScript, not React or Vue. Extending its existing helpers avoids adding an unrelated framework and preserves its existing transport, authentication and form handlers. Executed tests and limits are listed in V1.50-VERIFICATION.md.
